项目背景

AI 能回答问题，业务仍要自己串起资料和交付

业务人员做经营周报、行业研究与方案起草时，需要把分散的笔记、附件和数据库内容带进对话，再整理成能核对、能修改的文件。我将任务上下文、执行反馈和结果管理放在同一条流程中，减少重复切换与重新解释。

我的判断

让资料回到任务里，让结果可以追查

  1. 先选可验证的业务场景

    我按使用频率、可取得的资料和结果是否可验收，选择了经营周报、行业研究和方案起草。周报先做，因为关键数字可以独立核对。

  2. 明确资源跟随哪次输入

    我将模型、技能、知识库和数据库放进输入区。从笔记返回时保留原草稿，引用单独显示为标签，用户可以撤销。

  3. 拆开“答复”和“附件”的验收

    我将文件关联到会话，用可编辑工作簿承载明细。即使文件正确，如果用户明确要求的正文合计缺失，也要计为部分通过。

跨页引用与草稿保留验收规则

输入问题后打开知识库，引用指定笔记，再逐字比对返回后的草稿。

用例 移除笔记引用后，输入的原句与标点仍完整保留。
经营工作簿的双重核对验收规则

用下载后的 Excel 复核数值类型与公式，并对照数据库的独立查询结果。

用例 订单、销售、退款与净销售额的四列合计均可复算。

把需求写成可以复测的场景

关注点触发场景验收标准
资料引用输入一半后去知识库选择笔记返回保留原草稿；引用标签可见且可移除。
执行反馈工具执行超过一个交互周期显示当前阶段；详情可折叠，不能提前宣布完成。
文件交付用户要求 Excel 和正文结论文件可打开、公式可复算，正文回答明确要求的指标。
删除确认删除会话或文件先提示删除后不可恢复；确认后执行，取消则保留。

04交付管理

回复 / 文件 / 历史

  1. 提出业务问题

    从对话输入开始，选定模型；使用技能与员工定义工作方式。

  2. 连接任务资料

    选择笔记、文件和数据库，引用以标签保留；跨页查看资料时保留草稿。

  3. 理解执行进展

    执行步骤按需展开，清楚区分正在执行、等待信息、失败与完成。

  4. 检查并继续处理

    在会话空间查看生成文件，下载可编辑文档；核对数据后继续修改或创建定时任务。
