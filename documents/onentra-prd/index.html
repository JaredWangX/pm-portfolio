01价值判断

ONENTRA 面向需要反复整理资料、分析经营数据和交付办公文件的业务人员。经营周报、行业研究和方案起草表面上都是“写一份内容”，实际要经过找资料、确认口径、查询数据、组织结论、制作文件和反复修改。用户卡住的地方，是这些动作分散在模型、数据库、文档和聊天记录之间，已经说过的背景很难跟着任务走。

我的产品判断是：统一入口的价值不是把工具图标放在一起，而是让目标、资料、执行记录和交付物始终属于同一项任务。大模型处理自然语言任务、资料归纳与内容编排；程序承担身份校验、数据查询、金额计算、文件渲染和调度。字段明确的固定报表直接使用查询和模板，不必每次重新推理。

1.1 替代方案与竞争边界

方案优势与适用场景ONENTRA 的取舍
通用 AI 对话自由表达、内容起草与连续讨论；适合低结构任务。保留对话入口，但把资源、运行和文件关系显式保存，减少反复粘贴资料。
BI＋Office＋人工整理固定口径报表稳定、文件易于编辑；适合规范流程。保留确定性计算与可编辑文件能力，让模型补足非固定问题的理解与组织。
工作流搭建工具步骤明确时可配置节点与条件，便于复用。业务用户先完成一次任务，再将验证过的流程保存为自动化，避免先学复杂编排。
任务工作台＋受控执行目标变化时可解释、修改和追踪资料与结果。首期聚焦三个场景，控制工具权限和失败成本，不承诺开放式任务全部自动完成。

1.2 用户价值、业务价值与经济性

用户价值是少重复交代背景、少找文件、少把错误带入下一步。业务目标是提高首次可用交付率和任务复用率，并降低从准备资料到得到可用结果的总耗时。模型目标则是正确识别交付要求、选择必要工具、忠实使用来源、输出可校验结构；两者分开测量，不能用回复流畅度替代业务完成。

是否值得使用大模型的判断

以相同输入资料比较人工流程、规则模板和模型方案。总成本包含模型、检索、渲染、存储、人工核查与返工；单位成本用该批总成本除以验收通过任务数。只有质量门槛相同，节省的人工时间仍大于新增核查与运行成本，才把该场景推广为默认路径。

项目已具备对话引用、只读查询、办公文件生成与后台任务的实现依据。经营样例中的 63 笔订单、32,946 元净销售额用于核对数据链路，不作为营收或效率成果。我把这类可复核证据用于证明链路可行，把规模化收益交给统一口径的任务评测。

1.3 首期场景选择与排除依据

首期选择经营周报、行业研究和方案起草，是因为三类工作都存在重复收集资料、组织信息和交付文件的过程，但又能定义相对清楚的验收终点。经营周报用数值和口径校验，行业研究用来源和证据校验，方案起草用需求覆盖与可执行性校验。它们共同检验任务上下文的价值，也能暴露不同类型的模型错误。

场景原流程的成本适合自动化的部分与边界
经营周报在数据库、表格和文档间搬运数字，反复确认退款与统计范围。只读查询、汇总、图表和初稿可复用；口径缺失和异常原因仍须业务确认。
行业研究资料散落，观点与事实混在一起，改稿时难以追溯结论。归纳与引用关系可辅助；未访问到的来源不能写成已验证事实。
方案起草每次重新解释背景、受众、篇幅和输出格式。已授权资料与模板可复用；预算承诺、外部发送和最终决策保留人工确认。
固定标准报表字段、格式和规则已完全稳定。优先使用既有查询与模板，只在解释变化或临时分析时增加模型。

场景优先级综合考虑发生频率、资料可取得性、结果可核验性、错误影响和用户可接受的等待。能做出漂亮演示但缺少事实来源的任务不优先；流程很短、规则稳定、用传统工具已经足够的任务也不为了体现AI而增加调用。评审时先说明替代哪段工作，再说明模型参与哪一步，避免把“能聊天”写成业务需求。

1.4 业务指标与收益核算的完整口径

首次可用交付率以用户要求的正文和全部附件均通过为准；二次修改量区分正常创作修改与系统错误返工。正常修改说明用户继续推进工作，不能全部算作失败；纠正错误金额、补回遗漏附件和重新查找丢失来源，才计入产品造成的返工。

端到端耗时从资料准备开始，计入上传、配置、等待、核查和修正，到业务可用交付结束。成本按同批成功任务分摊模型、查询、渲染、存储、运维和人工核查。与人工流程对照时使用相同资料与交付标准，记录执行者熟悉程度，不把AI生成的简略结果与人工精修成果直接比较。复用率则以任务在修改少量参数后再次完成为准，不能用“保存了一个计划”代替真正被复用。

02需求描述

首期以三类任务验证通用入口：经营周报要求统计口径清楚且金额可复算；行业研究要求来源、结论与推测区分；方案起草要求结构完整、可继续修改并交付指定格式。三类任务共享上下文与文件体系，但验收标准不同。

需求编号核心需求交付定义
O-01 · P0输入与资源引用保留草稿、模型选择、技能、知识笔记、文件及数据库引用；发送前可见、可移除。
O-02 · P0模型与数据库接入连接测试与保存反馈清楚；自定义模型按配置调用，数据库只使用授权范围，凭据不回显。
O-03 · P0真实执行反馈当前阶段与阻塞原因可读，详细工具轨迹按需展开；不暴露无关 token 和缓存数字。
O-04 · P0正文和文件交付回答指定问题并交付可编辑 DOCX、PPTX、XLSX；正文、来源与附件使用同一口径。
O-05 · P0会话与文件管理历史记录与会话空间分工清楚；可搜索筛选；删除前明确提示不可恢复并确认。
O-06 · P1员工与任务复用员工保存职责和默认能力；计划保存调度规则，每次运行有独立记录，支持暂停和检查失败。

2.1 性能与非功能要求

维度产品要求验收口径
输入与导航交互反馈 ≤300ms；切换资源页和返回不能丢草稿；弹层适配手机视口。桌面与手机分别测试长文本、长列表、键盘打开和返回位置。
执行可感知稳定服务下首个有效执行状态 P95 ≤2s；文本首段目标 P95 ≤8s。网络连通但无内容的心跳不算有效阶段；按任务类型记录耗时。
复杂交付文件任务目标 P95 ≤120s；长任务保留明确阶段、取消或恢复路径。以上为目标门槛；查询、模型、渲染分段统计，超时与失败计入分母。
权限与隔离模型密钥和数据库凭据服务端保护；会话、资料、文件和任务按归属校验。跨身份读取、越权 SQL、任意地址访问和删除绕过均属阻断问题。
结果完整性关键数值、单位、来源和指定附件全通过才标记完成。文件存在、扩展名正确或工具返回成功，都不能单独构成任务通过。

明确排除自动付款、任意数据库写入、未授权的对外发送和无限循环执行。联网、MCP 与外部资源只有实际接入且获得授权后才能使用；页面显示开关不能被理解为工具已经执行。权限和预算限制必须在服务端生效。

2.2 任务、资源和产物的数据对象

任务上下文是整个产品的共同对象，不能分别散落在输入框、资源弹窗和后台计划中。一次提交固定原始要求与资源快照，运行记录引用这些对象，产物再关联具体运行。这样用户修改模型、删除资料或重新生成文件时，仍能理解旧结果是在什么条件下产生的。

对象核心字段关系与规则
会话 Sessionsession_id、owner、标题、消息与草稿状态。承载连续讨论；会话删除不默认撤销独立计划或外部执行，具体范围需确认。
任务 Tasktask_id、原始目标、必答项、输出格式、范围、引用资源。验收依据来自原始要求；模型建议可补充清单，但不能静默删除用户必答项。
运行 Runrun_id、attempt、状态、配置快照、开始与结束、错误和产物索引。每次重试为新尝试，关联原运行；不覆盖原失败证据。
资源 Resourceresource_id、类型、归属、版本、可用性和可使用范围。名称用于展示，ID用于引用；更名不应导致引用失效，删除则明确影响范围。
产物 Artifactartifact_id、run_id、文件名、格式、大小、校验状态、版本与来源。文件属于某次交付；局部修改产生新版本，不把旧链接指向不相关内容。
计划 Scheduleschedule_id、时区、频率、下次触发、任务模板与启用状态。计划和运行分开；暂停计划阻止后续触发，不伪装已取消当前运行。

2.3 用户角色和操作权限

普通使用者在自身授权范围内创建会话、引用资料、运行任务和管理产物；资源维护者配置模型与数据库连接并维护可用范围；工作空间管理者管理成员、共享和连接授权。界面可以隐藏不可用操作，但授权判断必须在服务端执行。一个用户知道文件ID，不等于有权下载该文件；连接测试成功，也不等于允许当前任务查询所有表。

共享资料与个人资料应有明确归属。共享动作显示对象、接收范围和权限变化，撤销共享后新请求不可再读取；已生成的成果是否仍可使用需要遵循对象归属和产品策略，不在后台悄悄删除历史文件。公开体验中的演示库与用户接入的真实库必须在界面和执行记录中分开标记，避免将演示数据当作企业经营事实。

2.4 可配置项与默认行为

模型选择、资源引用、联网和深度处理等设置按实际可用能力展示。无法使用的能力给出原因或配置入口，不提供看起来已开启但没有后端执行的开关。变更设置保留草稿；发送前冻结本次配置，正在运行的任务不因用户切换下次默认模型而改变。会话空间的类型、排序和视图仅改变展示，不触发重新生成或重新查询。

03流程设计

业务流程以用户交付目标为起点；系统流程以一次有边界的运行记录为单位。手动提交和定时触发都进入同一执行链，区别在于自动化任务不能临时等待一个在线用户回答，因此必须提前定义缺资料和失败策略。

默认采用有边界的工作流，只有工具结果影响下一步判断时才进入受控 Agent 循环。每次运行配置工具调用数、总时长与成本上限；工具结果进入模型前校验格式和来源。执行轨迹记录动作与证据，不要求展示模型内部思维过程。

系统图描述目标控制链。当前实现已有只读 SQL 校验、模型调用、办公渲染和运行记录；统一业务验收、局部修复与完整任务状态需要按功能验收逐项对齐，不能把文件渲染成功直接映射成整项任务完成。

3.1 节点间交接的数据和恢复位置

节点必须交付给下一节点的数据失败时的恢复位置
接收任务原始要求、已确认口径、身份、资源引用、请求键。字段错误回到输入；身份失败结束请求，不读取资料。
资源准备连接结果、资料版本、授权schema、工具能力清单。具体资源不可用时允许替换；保留未受影响的引用和草稿。
执行规划必答项、所需工具、参数、格式、调用预算和终止条件。关键口径缺失进入等待补充；无需工具的文本任务不强制规划复杂链路。
工具执行实际查询行、来源片段、执行状态及是否截断。重试只针对可安全重放的步骤；外部写入或发送必须确认实际执行状态。
内容与文件编排共同使用的事实对象、正文摘要、各格式结构及待补项。结构不合法可有限修复；事实缺失回到资源或口径，不靠模型补造。
联合校验逐项验收结果、文件有效性、数值对照和可交付范围。局部失败保留已验证产物，明确缺项后再决定修正或停止。

后台执行与浏览器连接应分离。用户离开页面、锁屏或断网，不应被当作任务取消；重新进入后通过运行ID查询真实状态，再补取缺失事件。用户主动取消时记录取消请求，并阻止尚未开始的后续步骤；已经完成的数据库读取不回滚，已经生成的文件是否保留应在结果区说明。

自动化任务在触发时读取已保存的任务模板与资源授权，生成独立运行快照。若连接权限已撤销、资料已删除或需要用户补充口径，本次运行记录明确失败或跳过原因，不无限等待。下一次触发是否继续执行由计划配置决定，不能把一次失败自动改成永久停用，也不能静默跳过所有失败批次。

3.2 循环和重试预算

循环只处理可定位的错误。SQL语法或字段错误先返回结构化原因，再允许一次重新规划；文件schema错误仅修复该格式；来源不足则等待用户。每个子步骤重试都消耗同一运行的总时间与调用预算，不能通过子循环重置预算。达到上限后返回可用部分和明确缺项，运行以部分完成或失败结束。

04大模型选型

我优先按任务节点选模型：SQL 规划要求字段、方言和查询意图稳定；资料总结要求忠实与引用；文件编排要求结构、数值和多格式一致。一个模型能完成三类工作，不代表每个节点都应采用相同参数和成本。

节点优先比较路径决定模型是否合格
任务路由固定指令规则 → 小参数分类模型。区分“解释如何做 PPT”和“生成 PPT”，识别否定与目标格式，不误触发文件工具。
SQL 规划限定单表 schema，用小模型先验证；失败再比较现有模型。字段、过滤、分组和聚合正确；通过 SQL 解析、表白名单与只读检查。
资料与回复小模型先跑短文归纳，长资料和复杂要求再升级。关键结论有来源，缺资料时如实说明；引用内容不改变系统权限。
文件编排结构化输出模型，按格式分别评测。DOCX 标题与正文完整，PPTX 可编辑，XLSX 公式和数值正确；截断不能伪装成功。

公开工作平台默认模型的服务标识为 qwen3.8-27b，同时支持兼容接口的自定义模型配置。选型矩阵以实际可接入候选为准，不用模型名代替能力证明。固定同题、工具返回和并发，比较正确性、结构成功率、P95 延迟、峰值资源占用及每次有效交付成本。小模型过硬性门槛、分组质量相近时优先使用；否则保留更强模型用于相应节点。

降级必须可见。用户明确选择某个模型时，连接失败不能偷偷换到另一个提供商；可以提示重试或由用户选择备用配置。LoRA 只在稳定的业务表达或结构生成错误上评估，并与 Prompt、检索优化作对照。权限控制、SQL 安全和金额复算不能交给微调解决。

成本口径

一次经营周报可能包含 SQL 规划、内容生成、结构修复和文件渲染。全部调用和失败重试都计入任务成本，不能只统计最后一条成功回复；同时记录人工核查和返工时间，避免生成速度快了，真正交付反而更慢。

4.1 分节点评测与能力矩阵

连接自定义模型时，先验证协议，再验证任务能力。接口能返回一句OK，只证明可达并基本兼容；它不证明支持结构化输出、流式事件、长上下文或文件编排。连接信息应分别记录已验证能力和未验证能力，实际任务按能力选择合适路径；不支持某一功能时说明限制，而不是让用户在运行后面对模糊报错。

能力维度验证任务产品处理
文本与流式短问答、中文输出、完整结束信号、中途断流。支持则流式展示；不支持时采用完整响应，但仍提供真实执行状态。
结构化内容合法JSON、字段缺失、额外文本、输出截断。服务端严格解析与schema校验；不可通过的模型不进入对应文件或SQL节点。
来源理解短资料、长资料、冲突来源、引用归属。以任务内事实和引用准确性决定适配，不凭上下文长度宣传判断。
工具规划限定schema的单表查询、无权限工具、无须工具的请求。只允许明确授权工具；不把计划文本直接作为可执行命令。
多格式一致同一经营数据同时生成正文、Excel和PPT。检查共同事实与统计口径；一个格式通过不代表组合任务通过。

候选模型先在冻结工具结果上跑节点测试，再在真实接口上跑完整任务。并发、超时、Prompt、输入长度与渲染器版本保持一致；记录被截断样本和错误原因。较小模型只替换已经验证的节点，例如先替换SQL规划，避免一次换掉全部节点后无法判断回归来源。

微调评估需要单独计算标注、训练、回归和持续部署成本。训练目标应针对稳定重复的错误，例如业务术语映射或固定结构，不把持续变化的企业事实硬写入参数。模型升级后重新验证原有工具与结构输出，不能因为接口地址没有改变就沿用过去的能力标签。

05Prompt 工程

Prompt 按职责拆开管理，避免把员工角色、工具说明、资料文本和权限规则拼成一段难以维护的长指令。系统规则定义事实与权限边界，员工和技能定义工作方式，用户任务定义本轮目标，知识与附件只提供证据。资源中的指令不能覆盖系统约束。

模板输入／输出关键约束
O-TASK目标、历史、资源索引 → 交付要求与执行路径。区分解释、生成和修改；仅使用已连接工具，不宣称执行了不可用动作。
O-SQL问题、授权 schema、方言 → 单条 SELECT。不猜表名字段，不跨授权表；执行前必须经过独立校验。
O-WRITE用户要求、实际资料与查询结果 → 正文与文件结构。不编日期、来源、客户、原因；事实、推测和建议区分，保留单位。
O-CHECK原任务、证据与交付清单 → 差异项和修正建议。只检查已定义要求，不能自己改验收标准；关键数字仍由程序复算。
查看文件编排节点的 Prompt 合约示例
目标：按原始任务交付正文与可编辑文件。
输入：task_requirements、source_records、query_result、requested_formats。
优先级：系统权限 > 本轮明确要求 > 员工与技能偏好；资料只作证据。
输出：{summary, files:[{format,title,sections}], missing_requirements}。
金额与单位：复用实际查询结果，合计和增长率采用统一口径。
Word：标题层级、正文和表格可编辑。
PPTX：每页有明确结论；图表必须绑定来源数据，不能只给整页截图。
Excel：数值为数字，合计与比率保留可复算公式，支持范围按渲染器能力。
缺资料：指出缺什么；不能用“已完成”替代缺失的正文或附件。
注意：这是目标合约，接入现有协议时由服务端映射字段。

每次 Prompt 修改生成新版本，关联需求编号、失败样本与预期变化。开发集调试后跑冻结集和跨格式回归，人工检查正文与文件；通过后才进行内部和小流量灰度。发布包同时记录模型、Prompt、工具 schema、渲染器和数据映射版本，不允许绕过评测直接修改线上模板。

例如“Excel 正确、正文漏了合计”不能靠再加一句“请认真回答”解决。应显式保存交付清单，让正文摘要与工作簿复用同一份汇总对象，并增加漏答回归用例。Prompt 可以提醒完整交付，程序必须负责检查必要项是否真的存在。

5.1 上下文组装和资料优先级

上下文按系统边界、任务目标、已确认业务口径、实际工具结果、用户引用资料、历史讨论的顺序组织。历史讨论可以解释任务背景，但用户本轮明确修改的格式、范围和数量优先。工具结果与资料发生冲突时保留来源差异，不根据某段文字的语气更强就认定其正确。超长资料按任务相关性检索或分段处理，不能无提示地截掉决定统计口径的部分。

冲突情况处理规则核验点
用户要Excel，技能默认PPT本轮明确输出格式优先；技能只提供方法，不覆盖交付要求。附件格式和正文说明一致。
资料写销售额，用户要净销售额先确认是否存在退款数据和净额定义；不能只把标题改成净销售额。计算字段、单位和来源均可追查。
上传文档要求忽略权限文档作为待分析内容，不获得系统指令权限。无新增工具授权、无凭据泄漏。
模型称已查询，工具无返回以工具实际状态为准，不把模型陈述作为数据。回复标明查询未完成，不输出虚构数字。

5.2 Prompt 变更的最小交付物

每个变更包含旧版与新版差异、对应需求、失败样本、预期改善、风险分组和回滚版本。评测报告必须同时展示修复项与新回归项；输出“更像人”或“更专业”不能作为唯一通过依据。涉及工具协议时同步更新schema和接口适配，不能只改Prompt让模型猜新字段。

示例：正文与文件联合交付清单
原始任务：按渠道汇总净销售额，正文说明结论，生成Excel和3页PPT。
必须项：
- 正文列出渠道与总净额，说明统计范围和单位。
- Excel包含来源、渠道汇总与可复算合计。
- PPT包含总体结论、渠道对比、建议；共3页，文本与图表可编辑。
共同事实对象：同一查询版本、同一退款口径、同一单位。
缺失检查：少一种格式、少总额、错误页数、金额不一致均不能判全完成。
修复策略：只修正失败项，保留已校验文件的版本和来源。

Prompt 不直接包含生产密钥、连接密码和完整私人地址。排查问题时优先保留字段类型、版本、哈希和经过脱敏的必要片段。内部评测可复现问题，但不能为了复现把所有客户资料无期限写进日志。保留范围与访问权限应与工作空间的数据使用约定一致。

06评测数据集

评测数据应能重建任务环境。一条样本不仅有问题和期望答案，还要保存输入资料、数据库 schema 与快照、权限身份、可用工具、模型与模板版本、期望文件和可执行断言。没有可复现环境，就很难分清模型退步、数据变化与连接失败。

任务集覆盖内容标准答案形式
经营分析渠道汇总、退款口径、空数据、零分母、中文列名、截断结果。独立 SQL 结果、预期单位、公式与正文必答项。
研究与方案多资料归纳、相互冲突、来源缺失、无证据的因果归因。关键事实、可引用来源、必须澄清项和可接受结论集合。
办公文件单格式与多格式、修改现有文件、页数和工作表、图表与公式。可打开、可编辑、内容与结构断言，辅以真实渲染截图。
权限与异常跨工作空间、SQL写入、恶意资料、模型超时、渲染中断、删除取消。必须拒绝的动作、应保留状态和错误反馈。
连续与自动化引用后返回、切换模型、追问修改、重复触发、后台重启。任务状态、资源快照、运行唯一性与文件归属。

发布评测按 180 个独立任务配置：经营分析、研究方案、办公文件、权限异常各 40 个，连续与自动化 20 个。文件组覆盖 DOCX、PPTX、XLSX 单独交付与组合交付；严重错误和历史失败另列强制回归项，不因样本配额已满而排除。

开发集用于调整 Prompt 与工具，冻结集用于发布，回归集收集真实失败。相同资料生成的任务、同一模板的改写和同一订单快照不能随机拆散后宣称互不相关；按资料来源和任务族隔离。若训练微调模型，另设训练与验证集合，并保留模型未见过的最终测试集。

数据、产品和测试共同标注：业务人员确认统计口径，研发提供工具边界，产品定义交付清单，测试复核预期文件。关键数字用程序校验；研究结论和写作质量采用双人抽样审核，分歧记录为规则澄清。只有授权、脱敏且保留来源的材料才能进入训练或长期评测库。

6.1 评测环境、标准文件与可复现性

经营任务使用固定数据库快照，研究任务使用冻结资料集合，文件任务保留标准结构与内容断言。一次测试开始前清理该测试创建的临时产物并恢复独立环境，禁止误删用户资料。模型输出不是唯一证据，数据库实际状态、文件内部结构、渲染结果和用户界面状态共同组成任务记录。

证据类型保存内容检查方式
数据基准表结构、允许范围、输入行、独立查询和预期聚合。直接复算统计值；验证过滤、空值、退款和零分母。
文件基准必需章节、页数、工作表、公式、数值、图表系列和来源。解析DOCX/PPTX/XLSX内部结构，并打开渲染检查裁切、溢出与空页。
过程基准任务输入、资源快照、工具事件、错误和重试。核对步骤是否实际发生，取消和失败后的动作是否符合约定。
权限基准测试身份、资源归属、共享范围和禁止访问对象。跨工作空间、猜测ID、过期授权与删除确认的负向测试。
标注记录标注规则、独立评分、争议和裁决。以一致标准复核，不用模型品牌或生成文风影响事实判定。

同一业务资料改写出的多道题属于同源任务族，按族分配开发、训练和测试集合。不能把一个Excel换个列名后当作完全独立测试数据。训练集若使用模型生成样本，必须经过事实和结构审核，保留生成来源，防止把模型自己的错误当成标准答案。

样本更新分两类：业务规则变更需要升级基准并保留旧版；模型失败只新增回归，不随意修改正确答案。每次报告注明评测集版本与有效样本数，数据损坏、依赖不可用和执行失败分别记录，不能把后两者统一排除后只报告顺利完成的任务。

07评测体系

评测的最小单位是一次任务，而不是一句回复。SQL 成功、文件生成成功、最终业务交付通过是三个不同层次。先用确定性检查守住数字、权限和文件，再评估解释与可用性，最后比较完成时间和成本。

层级与指标判定方法发布门槛
任务完整率必答项与指定产物全部满足的任务／全部有效任务。P0关键集全通过；部分交付不计入成功，失败和超时留在分母。
事实与数值一致独立查询、正文、表格和图表使用同一统计范围；检查单位、退款、分母。关键数值逐项一致；任何无依据补造或错误口径直接阻断。
文件可用性打开文件并检查可编辑结构、公式重算、表格列数和真实渲染。指定格式必须实际生成；图片或PDF不能替代可编辑PPTX。
资源与权限检查来源引用、连接选择、租户归属、只读限制和敏感信息。越权、泄密、未确认删除为零容忍，不用平均分冲抵。
稳定性与效率关键任务重复3次，记录均值与全通过率；端到端计时包括准备、核查和返工。质量不退步后才比较耗时和成本；按任务类型单独报告。

7.1 人工、程序与模型评审如何分工

程序检查 schema、数值、文件内部结构与数据库状态；业务审核检查结论是否回答原问题；模型评审可辅助发现漏项、重复和语义矛盾，但不得独立判断自己是否完成任务。对于没有唯一文本答案的研究与方案，采用需求覆盖、来源支持、结构清楚、可继续使用四项评分，并给出具体扣分依据。

每次变更先跑对应节点，再跑跨资源、跨格式关键链路。保留模型输入输出、工具结果、错误类别与产物哈希；评测前恢复同一数据快照，避免上一轮生成文件或修改状态影响下一轮。评审只看候选编号，不展示模型品牌或版本，以减少偏好干扰。

线上监测关注失败阶段、重试、人工改写、文件打开与继续修改；点击下载只说明拿到文件，不能当作交付满意。新增失败先复现并归类，再进入回归集，不通过持续加长 Prompt 掩盖工具或数据问题。

7.2 任务判分矩阵与通过条件

检查项通过部分完成／失败
需求覆盖原始任务的必答项、输出格式、页数和范围均满足。缺少一项必要交付记部分完成；完全不可用或无有效结果记失败。
事实正确结论与来源一致，关键数字独立复算通过。数值错误、错误口径、无依据事实为硬失败，不用版式评分抵消。
文件可用指定格式真实存在、可以打开与编辑，内容不溢出。只有链接、空文件、整页图片冒充可编辑PPT，均不通过。
过程可控工具经过授权，取消和重试符合状态规则。越权操作、重复副作用、取消后继续启动新步骤为阻断。
体验完成用户能找到结论和文件，失败后可理解下一步。正文只有“已生成”、来源无法定位、状态卡在执行中为需修复项。

评分先执行硬断言，再评估内容组织。写作质量可用0至2分量表：0分表示未覆盖或无法使用，1分表示基本覆盖但需要明显重组，2分表示结构清楚且可直接继续工作。需求覆盖、来源支持、逻辑组织和可操作性分别打分并写出依据。关键数字与权限不进入这类可补偿的主观加分项。

基于同一输入重复执行时，记录每次是否通过以及三次全部通过的比例；不要把三次尝试中最好的一次当作稳定结果。端到端耗时同时报告成功任务与失败任务的分布，失败重试成本计入总成本。模型升级报告逐题差异，对复杂任务族和小样本组单独复核，不能只看整体平均。

7.3 验收执行顺序与缺陷归属

先检查资料和连接，再验证节点输出与工具执行，随后做正文文件联合验收，最后检查真实页面。发现错误后按来源定位：schema错误归接口或生成结构，金额错误先核对SQL和计算，事实遗漏检查需求清单与上下文，文字裁切归渲染和布局。归属用于确定修复位置，不把所有失败笼统交给“换个更强模型”。

复测必须覆盖直接受影响的场景和相邻链路。例如修改Excel公式解析，不只测一张表，还要测引用该表的PPT图表和正文摘要；修改模型连接，不只测连接成功，还要测流式中断、过期凭据和已保存自动化任务。验收记录保留输入、预期、实际、证据与责任人角色，便于复查而不是只留下一个通过勾选。

08效果保障

质量保障贯穿输入、执行和交付。对用户最重要的不是系统展示了多少技术细节，而是知道这一步用了什么依据、哪部分完成了、哪里需要自己判断。默认展示阶段摘要和阻塞项，详细轨迹可展开，既保持可理解，也保留追查能力。

控制层必须执行的检查失败处理
输入与身份验证会话归属、资源权限、模型连接、文件大小和可读性。定位具体资源，保留草稿；不把凭据写进模型上下文。
数据库解析SQL，只读事务与表列范围控制；限制超时、行数和返回体积。返回明确错误；截断结果标记truncated，不把前50行冒充全量明细。
外部工具与资料工具白名单、参数校验、地址限制；资料中的指令作为普通内容。阻止越权动作；资料冲突时展示差异，不自行假定唯一事实。
文件渲染模型仅输出受限结构；程序校验格式、数组长度、公式与生成文件。保留已完成内容，指出失败格式；不能把空文件发成成功结果。
联合交付正文必答项、来源数据与附件逐项核对，关键指标复算。部分完成与完成分开；局部修正生成新版本，保留来源关系。
运行与重试总时长、调用预算、重复触发控制；定时任务按任务与触发批次去重。超过限制停止；外部有副作用的操作不能无条件重放。

当前工作平台已有 SQL 解析与只读查询、连接凭据服务端保护、结构化办公渲染、任务运行和文件归属记录。产品层进一步要求：工具成功不能代替任务成功，界面进度只能来自真实事件；取消意味着停止后续步骤，已完成的查询和文件需说明保留情况。

一个必须被拦住的“伪完成”

用户要求“正文告诉我合计，再给Excel”，模型只回“文件已生成”。即使工作簿的32,946元完全正确，这次也缺少一项交付。应保留正确附件并补齐正文，不能让用户再打开文件替系统完成最后一步。

8.1 数据库查询和业务口径控制

当前自定义数据库路径以选定表或视图的单表只读查询为边界，涉及跨表分析时应由授权的数据视图提供清楚结构，不能把用户的自然语言直接拼成任意SQL。语句需经过解析，检查查询类型、表、字段和允许表达式，再在受限连接中执行。查询输出包含列名、行、是否截断及单位信息；结果被截断时，正文必须说明覆盖范围。

分析总额应优先在数据库中聚合，而不是取前50条明细让模型估算全量。空结果表示筛选后无记录，不能自动解释为全部销售额为零；NULL表示未知或缺失，不等同于0。退款、含税、币种与时间窗口必须与需求一致，无法确认时先询问或明确限制，不在自然语言中自行补一个合理口径。

8.2 文档生成的格式级验收

格式必须检查的内容常见失败与处理
DOCX标题层级、正文、表格、页边距、可编辑文本和来源。目录与正文不一致、长表截断、空标题；按结构修复后再次渲染。
PPTX指定页数、每页结论、可编辑文本与图表、图表数据、边界和字号。整页截图、文字出框、图例遮挡、数据与正文不一致；逐页检查，不能只看封面。
XLSX数值类型、单位、公式引用、跨表关系、合计、百分比和重算结果。数值存成文本、合计包含自己、错分母、循环引用；限制公式范围并独立复算。
多格式交付同一来源、同一统计口径、同一关键指标和对应版本。正文已改但附件未更新；只修一处不能判整体通过，需跨产物重新核对。

文件与正文共同使用一个经过确认的事实对象，包含指标名称、值、单位、范围和来源。渲染器负责把结构变成文件，模型负责内容编排，两者都不能单独宣布任务完成。下载前校验文件存在、格式和大小，下载时再次验证归属；失败不能只返回一个看似可点击但没有内容的链接。

8.3 重试、取消与删除的副作用控制

只读查询可在允许范围内重放；文件生成要避免把重复结果写成无法区分的多个文件；外部发送和数据写入必须先确定上一轮是否已经执行。删除确认弹层显示对象名、范围和不可恢复说明，取消不发删除请求；确认后等待服务端结果，再更新列表。网络失败时显示状态未知并重新核对，不能先把界面项移除后假定删除成功。

9.2 状态机与对象关系

会话承载持续讨论；一次提交对应一次运行；输入资料与生成文件分别关联运行；计划只保存触发规则，不代表某次已成功。目标状态为：待执行 → 执行中 → 等待补充／部分完成／完成／失败／已取消。只有必答项与必交文件全部通过才能进入完成；等待补充恢复后沿用上下文，重试产生关联的新尝试，不能覆盖原失败证据。

9.4 灰度、回滚与验收协作

按“单次任务可靠 → 多格式交付 → 验证后复用”为顺序。产品维护场景和验收清单，研发维护接口、工具限制与版本，测试维护冻结集和异常回归；业务评审确认口径及交付可用性。新模型和Prompt先内部验证，再按稳定身份做5%、20%、全量放量；文件格式和连接器分别开关，避免单点故障扩散。

出现越权、凭据泄露或关键金额错误立即停止相关能力并切回稳定版本；任务完成率下降、延迟或单位成本超出约定预算时暂停放量。回滚保留已有文件、运行记录和用户数据，不通过清库恢复。单次任务质量未过关之前，不把相同流程扩大为后台批量执行。

9.5 连接管理的字段、校验和编辑行为

功能字段与保存规则失败与修改规则

9.6 会话、空间与任务的交互细则

会话历史用于找回讨论，会话空间用于查看本会话引用和产物，完整文件页用于跨会话管理。三者使用不同标题和范围提示，切换“本会话／全部会话”不能偷偷改变当前对话。搜索、类型筛选、排序和列表／网格视图维持一致高度与选中状态，空结果区分“没有文件”和“筛选后没有结果”，并提供清除筛选入口。

输入草稿与引用资源分别保存；打开模型、技能、知识或数据库选择器，已有文字不丢失。关闭侧栏后主内容自动释放宽度，标题与折叠按钮不重叠；弹层打开后不因鼠标短暂移开而关闭。移动端弹层在可视区域内滚动，关闭、确认和错误提示可达，系统键盘出现后不遮住提交入口。

执行区默认显示阶段、简短结果和必要动作，工具详情折叠。阶段更新来自真实事件，不用固定倒计时制造进度。失败后区分模型连接、资料读取、查询和文件生成，保留原草稿、引用和已完成成果；继续修改时明确沿用哪个文件版本和哪份数据快照。

9.7 定时任务与运行记录

规则约定验收条件
时间与触发展示明确时区；当前业务默认Asia/Shanghai。计划保存后返回下次触发。前端时间、后台计算和运行记录一致，不按访客浏览器时区悄悄改变计划。
唯一运行按计划、触发批次和归属建立唯一键；重试为同一批次的不同attempt。重复调度不重复生成主运行；重试记录可追溯。
暂停与恢复暂停阻止后续触发；已运行任务单独显示并可按能力取消。开关状态不代替执行结果；恢复后清楚显示下次时间。
失败与补跑区分资源失效、模型失败、渲染失败和服务中断；补跑需明确数据范围。不能把补跑时的新数据冒充原批次快照；不自动制造一串重复文件。

9.8 接口事件与状态一致性

目标事件协议示例：断流、重试与部分交付
事件公共字段：request_id、run_id、attempt、event_id、type。
run_start：创建运行并固定本次资源配置。
tool_status：阶段、工具、开始/结束/失败；不能只有无意义的“执行中”。
message_delta：正文增量，按event_id去重。
artifact_end：单个文件完成，附格式、版本与校验结果；不代表整项任务完成。
run_end：带completed_requirements、missing_requirements和最终状态。
run_error：错误类别、可恢复步骤和保留产物。
断流恢复：先查询run_id状态，再从最后event_id补取；不重复追加相同正文。
目标协议为联调要求，需与现有SSE事件逐项映射，不直接假定字段已部署。

客户端只根据服务端的运行状态和验收结果展示完成。创建任务、收到首条事件、生成一个文件、浏览器连接结束，都是不同事件。接口错误统一区分参数错误、身份权限、资源不可达、限流、执行失败和部分交付，提供明确恢复动作；服务端内部堆栈、密钥和连接信息不得进入用户错误消息。

9.9 需求追踪与发布准入

需求编号贯穿原型、接口、测试样本、缺陷和发布记录。每个P0需求至少覆盖正常、空数据、无权限、依赖失败和用户撤销等适用路径；不适用的分支写明原因。发布评审同时核对功能实现、数据口径、模型评测、跨端交互和回滚包。涉及权限、金额、重复执行与不可恢复删除的缺陷不能延期放行，普通体验优化则按阻断程度与发生频率排序。
