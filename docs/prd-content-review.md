# 两份 AI 产品需求文档的内容核对

## 范围

重写 Wanso 和 ONENTRA 的网页 PRD，均采用价值判断、需求描述、流程设计、模型选型、Prompt 工程、评测数据集、评测体系、效果保障、功能说明九步结构。首页两个文档入口同步更新。复盘文章、产品页面、视频、模型服务及生产配置不在本次修改范围；未增加 PDF 下载和页面更新时间。

两篇均包含需求编号、优先级、验收目标、用户流程和系统流程、异常分支、Prompt 合约示例、数据集字段、指标口径、硬性阻断项、接口映射和灰度回滚。流程图使用可选择文字的 HTML 与 CSS，窄屏按节点和分支纵向阅读，不依赖远端图表脚本。

## 实现证据

- Wanso 原生服务的 `server.py`：意图与回答分开配置，包含搜索、追问、菜单及比较分流。`compare_api.py`：门店配对与菜单比较。具体部署可覆盖模型默认配置，因此文中将模型名写为代码基线，而非最优选型结论。
- 本仓库 `server/wanso.mjs`：作品网页的接口、消息长度、并发限制、候选 ID 白名单和菜单价格回填。原生与网页的协议明确区分。
- 工作平台当前工作仓库 `server/model.mjs`、`workspace.mjs`、`connections.py`：自定义模型、数据连接、SQL 规划和只读查询。文中没有把早期只保存连接草稿的旧实现当成当前能力。
- 工作平台 `server/office.mjs`、`office_render.py`、`workspace.py`：结构化文档生成、数值和公式处理、后台运行与文件归属。正文与附件的统一业务验收、目标状态机和新增事件字段写为产品要求，未宣称本次已上线这些功能。
- Talos Agent 的 `origin/release-v2.1` 架构说明用于理解会话、工具、沙盒与事件流的职责划分；未读取 main 作为业务基线，也未把 Talos 完整能力写成公开作品已全部实现。
- 现有作品材料和 `native-fidelity-review.md` 保留 Wanso 三轮内测的来源与口径。63 笔订单、32,946 元属于合成经营库的验收样例，不是客户营收。

## 数字与事实边界

响应目标、240 / 180 个任务的建集配额、3 次重复执行、5% / 20% 灰度和修复次数均为本次制定的要求，不是已经完成的实验结果。未编造模型对比成绩、单位成本、生产可用性或业务收益。训练集、验证集、开发评测集、冻结测试集与回归集按用途区分，并要求同源任务隔离。

## 方法参考

评测按任务、执行轨迹与最终结果分层，确定性检查和人工判断各有职责；模型自述完成不作为业务完成证据。此组织方式与 [Anthropic 的 Agent 评测说明](https://www.anthropic.com/research/demystifying-evals-for-ai-agents)核对，公开正文采用两个项目自己的场景和规则，没有搬用外部案例成绩。

固定流程优先采用受控工作流，只有下一步确实依赖工具结果时才引入循环；架构选择应服务具体任务与操作边界。该边界参考 [Google Cloud 的 Agent 架构模式说明](https://docs.cloud.google.com/architecture/choose-design-pattern-agentic-ai-system/)，不据此声称项目已具备开放式自主执行能力。
